# 交通路标识别

上传一张任意尺寸的街景图，返回每个路标的位置和中文含义，并在原图上画出框。

上一版发布在 [Traffic-sign-recognition-project](https://github.com/LazyCharles07/Traffic-sign-recognition-project)。那一版用两个分开训练的模型：YOLOv8 在整张图里找框，ResNet-18 只看裁下来的小图，写出中文含义。页面上的含义来自 ResNet-18。这一版没有重训这两个模型，`weights/best.pt` 和 `weights/best_model.pth` 还是原来的文件。

## 相对上一版增加了什么

### 半截框补全

检测把握低于 0.60 的框，用现成的抠图模型从框中心往外补，看能不能把半截牌子补成整块。权重是 `weights/mobile_sam.pt`，大约 40 MB，不用训练。文件不在时程序会自己下载；下载失败就仍用原来的框。

补完后的分类把握达到 0.70 才换成新框。原来分类把握已经达到 0.90、新框反而变小的，仍用原框。把握已经达到 0.60 的框不补，免得一根杆上的几块牌子被连成一块。这个模型不知道牌子是什么意思，也找不回检测完全没框到的牌子。

候选也放宽了。上一版丢掉检测把握低于 0.10 的框。这一版 0.05 以上都先留下，最后只按分类把握筛：低于 0.70 的不显示。检测把握低、分类很有把握的框可以留下。

### 三个视觉大模型

上传一张图，页面出四张结果。第一张是检测、补全，再由分类模型写含义。另外三张由千问、智谱、DeepSeek 各自找框，含义仍交给分类模型。

密钥写在 `.env`，不要发给别人，也不要提交。把 `.env.example` 复制成 `.env` 后填空，再重启服务。哪一家没填，那一格会提示未配置，另外三格照常出图。

- 千问：`qwen3.8-flash`，地址 `https://dashscope.aliyuncs.com/compatible-mode/v1`
- 智谱：`glm-5v-turbo`，地址 `https://open.bigmodel.cn/api/paas/v4`。不先写一段内部分析。
- DeepSeek：`deepseek-flash`，地址 `https://api.deepseek.com`

每家再加一项 `QWEN_API_KEY`、`GLM_API_KEY` 或 `DEEPSEEK_API_KEY`。

### 登录和排队

打开网页要先登录。账号来自 `LOGIN_USERNAME` 和 `LOGIN_PASSWORD`。这两项都没写时，用户名和密码都是 `demo`。登录后浏览器保存一张 12 小时的凭证。这是页面账号，不是三家模型的密钥。公开仓库里不要放真实密码；Ubuntu 上的 `.env` 里把 `LOGIN_PASSWORD` 和 `JWT_SECRET` 改成自己的。

上传之后接口马上返回一个编号，图片进入队列，一次只识别一张。页面每隔两秒来问一次结果。本机直接运行、没有设置 `REDIS_URL` 时，队列就在这个进程里。用 Docker 启动时，Compose 会带上 Redis。图片和识别结果都不写到硬盘，编号两小时后失效。

### 对照页

用浏览器打开 `对照.html`。先点一张街景，再点两种识别方式，左右并排看。图下面有一句这张图上的结果。四种做法都在里面：

1. 检测找框，分类模型写含义。
2. 大模型找框，分类模型写含义。
3. 检测找框，大模型写含义。
4. 大模型自己找框，也自己写含义。

截图在 `test_results`、`test_results_分类`、`test_results_全流程`。对照页要和这三个文件夹放在同一目录。

同一批街景上，后三种接法差在这些地方：

- 只让大模型找框、含义仍用分类模型：景山上面的禁止掉头，三家都能框到，分类也对。同里的「停」框得住，含义仍是禁止向右转弯。DeepSeek 在同里没有留下框。
- 框仍用检测的，含义改由大模型写：同里三家都写成禁止停车。深圳的三角写成地铁施工。东营左缘那条误框，千问和智谱写成看不清。景山的禁止掉头仍然没有，因为检测没给出这个框。
- 找框和含义都交给大模型：同里写成禁止停车。景山的禁止掉头和「大型载客汽车」能分开框出，智谱把上面合成了一句。东营没有左缘误报。杭州近处四块，千问没有多框；智谱和 DeepSeek 会把远处的小牌子也框进来。

## 流程

1. 整张原图交给 YOLOv8，得到框，以及它对这个框有多大把握。把握最高是 1。
2. 把握低于 0.05 的框丢掉。
3. 两个框叠在一起，重叠部分达到二者合起来范围的一半时，只留把握更高的那个。
4. 检测把握已经达到 0.60 的框不再改。低于 0.60 的框，才用中心点试着补成整块牌子。补完后的分类把握达到 0.70 才采用。原来分类把握已经达到 0.90、新框反而变小的，仍用原框。
5. 按补全后的框从原图裁出小图。裁的时候四边各向外多留约 10%，以免边缘被切掉。画回原图的是补全后的框。
6. 小图缩放到 224×224，送进 ResNet-18，得到类别和分类把握。
7. 分类把握低于 0.70 的不显示。检测把握低一些的框可以留下来。
8. 同一张图再发给千问、智谱、DeepSeek，各自另找一套框，含义仍用第 6 步的分类模型。页面上四张图一起出。

类别来自 Kaggle 上的 [TT100K](https://www.kaggle.com/datasets/braunge/tt100k)。只保留训练集里至少出现 100 次的类别。这一版是 50 类，编号 0 到 49，名单在 `weights/dataset.yaml`。

上传的图片不会存到硬盘。本机调试和部署之后，网页都只从 `127.0.0.1` 打开。从 Windows 看 Ubuntu 上的页面，要先建 SSH 隧道，见「部署到 Ubuntu」。

## 本地运行

`weights/best.pt` 是训练好的检测模型，按边长 960 训练的。启动时加上 `--imgsz 960`，表示送给检测器的图片边长。`weights/best_model.pth` 是训练好的分类模型，不要用检测文件把它盖掉。

```bash
pip install -r requirements.txt
py -3.13 demo.py --imgsz 960
```

浏览器打开 [http://127.0.0.1:8000](http://127.0.0.1:8000)，先登录再上传。没在 `.env` 里设置账号时，用户名和密码都是 `demo`。电脑没有可用的显卡时，一张图大约要几十秒。密钥怎么填，写在上面「三个视觉大模型」一节。对照页是 `对照.html`，用浏览器直接打开，不经过这个服务，也不用登录。

## 部署到 Ubuntu

服务跑在 Ubuntu 上，80 端口只绑在那台电脑自己的 `127.0.0.1`。同一局域网里的别人不能直接打开。容器内部仍用 `0.0.0.0`，那只是让 nginx 容器能把请求转给识别服务，不会把 8000 端口露到局域网。

从 Windows 看页面时，用 SSH 建一条隧道：Windows 的 `127.0.0.1:8080` 转到 Ubuntu 的 `127.0.0.1:80`。隧道不断，页面才能开。

### Ubuntu 上

1. 安装并打开 SSH 服务，让 Windows 能登进来：

```bash
sudo apt update
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
```

查看这台电脑在局域网上的地址：

```bash
ip -4 addr
```

记下形如 `192.168.x.x` 的地址，以及登录用户名。

2. 安装 Docker Engine 和 Compose 插件。项目目录里放好：

- `weights/best.pt`、`weights/best_model.pth`、`weights/dataset.yaml`、`weights/mobile_sam.pt`
- `.env`：由 `.env.example` 复制来，填上三家密钥。这个文件只留在 Ubuntu 的项目目录里，不写进镜像。

3. 在项目目录启动：

```bash
docker compose up -d --build
```

第一次会下载 Python 和 CPU 版 PyTorch，镜像比较大，还要等检测模型加载。加载完成前网页还打不开。看进度：

```bash
docker compose logs -f app
```

出现监听地址后，坐在 Ubuntu 前的浏览器打开 `http://127.0.0.1/`。上传的图片不会存到硬盘。页面要先登录，没另设账号时用户名和密码都是 `demo`。上传后先拿到编号，识别在队列里一次做一张，页面过几秒再来取结果。nginx 单次请求最多等 60 秒。停掉服务：`docker compose down`。

### Windows 上

另开一个终端，不要关掉。把用户名和 IP 换成上一步记下的：

```bash
ssh -L 8080:127.0.0.1:80 用户名@192.168.x.x
```

登录成功后这个窗口留着。浏览器打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)。关掉这个 SSH 窗口，页面就断了。

## 实验结果

分类看的是裁下来的小图。这些小图按类别分成三份：训练用来学习，验证用来挑选最好的一轮，测试留到最后、不参与挑选。检测看的是数据集自带的验证集，共 3598 张图、10823 个框。

下面四个数的意思是：

- 精度：找出来的框里，有多少确实框住了标志。
- 召回：应该找到的标志里，实际找到了多少。
- mAP50：框和真实位置至少重叠一半就算对，再把各类合成一个分。
- mAP50-95：重叠要求从一半一直收到 95%，更严，所以分数更低。

### 分类器 ResNet-18

训练 20 轮，每次放进 128 张小图，用两块 T4。模型里大约有 1120 万个要学习的数。最好的是第 14 轮，验证准确率 0.9980。测试准确率 0.9976，7091 张里对了 7074 张，错了 17 张。这些小图是按标注紧紧裁出来的，所以这个准确率比拿整张街景去测要高。

### 检测器 YOLOv8

表里的数是训练结束、模型存成文件之后再测的。训练过程中最后一轮的 mAP50-95 是 0.808，存成文件后再测是 0.800，会略低一点。


| 训练          | 时间      | 精度    | 召回    | mAP50 | mAP50-95 |
| ----------- | ------- | ----- | ----- | ----- | -------- |
| 边长 640，30 轮 | 4.99 小时 | 0.891 | 0.713 | 0.835 | 0.684    |
| 边长 960，22 轮 | 4.85 小时 | 0.942 | 0.854 | 0.941 | 0.795    |
| 边长 960，26 轮 | 5.89 小时 | 0.941 | 0.865 | 0.944 | 0.800    |


26 轮这一版的最后五轮已经停住了。召回在 0.863 到 0.867 之间，mAP50-95 从第 23 轮起就是 0.808。训练时的误差还在变小，验证集上的框没有更准。现在本地用的就是这一版。

和边长 640 那一版比，几类原先容易漏掉的标志，召回提高了：

- 限速 40：0.606 → 0.844
- 禁止二轮摩托车：0.567 → 0.760
- 禁止掉头：0.652 → 0.772

### 七张街景测试图

上一版用边长 960 的权重、还没有补全时：

- 月亮：限速 40 和禁止停车都对。
- 东营：立柱上的三块牌子都对。
- 杭州：限速 50、禁止停车、机动车行驶、非机动车行驶都对。
- 深圳：上面的施工三角框对了。限速 40 没有框。
- 北京禁摩：只框住圆牌的一部分，含义错成了禁止鸣喇叭。
- 景山后街：禁止掉头没有框。禁止停车只剩一部分。
- 同里：「停」字牌的框是对的，含义是禁止向右转弯。训练集里的禁止停车是蓝底红叉，和这个「停」字牌不是同一种画法。

加上补全、含义仍由分类模型写之后：

- 月亮：没变，两块都对。
- 东营：杆上三块仍对。左边缘多了一条靠右侧道路行驶。
- 杭州：四块主标志仍对，多了一块禁止停车。
- 深圳：施工三角仍在，限速 40 这次框到了。
- 北京禁摩：含义改对了，是禁止二轮摩托车驶入。框还是没圈满整块圆牌。
- 景山后街：禁止停车的框比上一版完整。禁止掉头仍然没有。
- 同里：框在，含义仍是禁止向右转弯。

大模型参加之后的差别，写在上面「对照页」一节。

训练集里的照片大多是腾讯街景，标志在画面里很小。训练时还会把四张图拼成一张，标志被缩得更小。所以模型很少见过一块牌子占满画面的照片。边长改成 960 之后，这种大框算得出来，只是训练时几乎没见过。补全只能沿着已经找到的框往外长，检测完全没框到的牌子补不出来。
